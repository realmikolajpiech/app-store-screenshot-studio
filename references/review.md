# Review against the visual benchmark at three scales

## Compare actual images, not the plan

For a new direction, inspect the finished opener and one contrasting frame beside
the selected reference at a comparable frame size. Compare the individual panels
as well as the strips; a large Dribbble presentation can make detail look more
impressive than it will in a store thumbnail. Use the user-approved artwork as
the benchmark for narrow revisions instead of reopening its direction.

Check these separately from factual and file validation:

| Dimension | Look for in the render |
| --- | --- |
| Visual idea | A compelling subject and relationship to the product; the first impression supports the promise |
| Typographic character | Deliberate word emphasis, width/weight contrast, line shapes and optical spacing suited to the brand |
| Image selection | A useful, well-cropped photo, content item or illustration with the intended energy and enough quality |
| Spatial finish | Assets feel composed together through scale, occlusion, perspective, light or coherent graphic treatment |
| Identity | Recognizable app anchors with a purposeful creative extension; consistent material and photographic language |
| Sequence | A clear progression and controlled rhythm at set level, including places where repetition is deliberate |

For each material weakness, record the visible symptom, the specific reference
decision that exposes the gap and the next correction. For example: “The event
photo sits in a tiny separate footer; the reference makes content the focal
mass; enlarge and integrate the event scene with the device.” Avoid unsupported
quality scores, “looks premium” verdicts and checkmarks based on the prompt.

Fix visible gaps before expanding the series. Reassess the revised pixels;
writing a stronger brief alone does not demonstrate a stronger image.

For a revision or second set, compare against the strongest previous render as
well as the external benchmark. Identify which qualities survived and which
regressed: scale, silhouette, integration, texture, typography and set rhythm.
Satisfying the newest feedback is necessary but insufficient. If a font/palette
change also loses the original spatial finish, revise the stronger artwork with
explicit invariants instead of introducing another visual world. When a genuinely
new direction is requested, preserve the quality benchmark, not its literal layout.
Do not expand to the remaining frames while those first comparisons show a
regression. This is an internal correction step, not a mandatory user approval.

## Full resolution: truth and craft

Compare source and final side by side. Read the headline, key labels, names,
dates, time ranges, totals, percentages and selected states. Check hardware
proportions, fingers if present, distorted glyphs, card edges, diacritics and
background continuity. Ensure real-looking states do not contradict the app.

Inspect all replacements, not just the headline: a school or name may remain in
the phone, breakout, conversation avatar or tiny secondary card. A model's
confident rendering is not factual verification. Correct drift before export.

## Thumbnail: hierarchy

View at the approximate width of the placement (try 160 and 320 pixels wide as
diagnostic previews, not universal platform rules). Is the main outcome readable
without zoom? Does the UI focal region explain why the headline is credible?
Does a card touch the text? Is type too small because guides drove the layout?

The actual interface can contain small details. The selling point should be
visible without reading every row.

Temporarily hiding marketing copy can reveal whether the imagery contributes
anything. Use this as a diagnosis, not a requirement that every feature be
understandable without words: typography-led and atmospheric campaigns may
depend on the combination. Restore the copy and judge the whole promise.
Keep secondary text that orients, explains or reassures; remove redundant lines,
filler and unsupported proof. A single message can have several supporting layers.

## Contact sheet: campaign rhythm

Build the sheet from explicit selected export paths. Inspect dominant silhouettes,
adjacent device leans, type placement, contrast, pacing and the first few frames'
story. Check that variety remains coherent with the app. Color changes alone do
not fix identical compositions. Conversely, don't destroy a calm consistent set
just to satisfy an arbitrary variety quota.

Inspect each frame independently too. Shared scenes or panoramic devices may
connect panels; the essential promise still needs to survive an isolated store
preview. Don't assume the Dribbble strip's gaps, rounded corners or backdrop are
part of the actual uploaded asset. Honor explicit device/pose constraints.

## Product specificity

Check whether choices follow this product's content, audience and identity.
Shared category benefits are legitimate; a campaign does not need a unique
feature to deserve strong art direction. A competitor-swap thought experiment
can expose default styling, but is not an automatic rejection of a valid idea.

Ask what the expressive layers contribute: identity, context, feeling, emphasis
or explanation. Keep a well-integrated atmosphere even when it is not factual
proof. Remove incidental embellishment competing with the story. A large prop
can be the right focal subject when it expresses the benefit; size alone is not
a failure. When repetition feels dull, change the focal relationship or reading
order; when it creates a coherent calm sequence, preserve it.

## Delivery check

Confirm each new creative or visual revision has an actual generation/editing
result recorded in its provenance. A generation prompt without a completed call,
or a generated decoration pasted onto a scripted campaign, does not satisfy the
production requirement. Keep this separate from visual review: generated output
can still fail the benchmark and require another iteration.

Validate decoded dimensions, file format and absence of alpha. Check the delivery
folder contains only selected upload files, not contact sheets, scripts, source
captures or abandoned versions. Do not create archives unless explicitly asked.
Generate previews again after any approved revision;
old previews must not be presented as current. Distinguish visual review,
automated file validation and unperformed store upload/preview checks.

If the user wants evidence of conversion, propose a testable hypothesis, audience,
primary metric and controlled comparison. Do not call a visual preference a win
or fabricate test outcomes. Do not access analytics or run tests on a live listing
without the user's requested scope.
